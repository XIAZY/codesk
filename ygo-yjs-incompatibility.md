# ygo places a Yjs update with `rightOrigin` at the wrong position

## Problem

`github.com/reearth/ygo` does not materialize the same text as JavaScript Yjs for a small valid Yjs update sequence.

The repro is:

1. Yjs client `1` inserts `"ab"`.
2. Yjs client `2` receives that update.
3. Yjs client `2` inserts `"X"` at index `1`, between `"a"` and `"b"`.

Yjs materializes `"aXb"`. ygo `ApplyUpdateV1` materializes `"abX"`.

## Versions tested

```text
github.com/reearth/ygo v1.7.1
yjs 13.6.30
```

## Minimal reproduction

Create a temporary module:

```sh
mkdir /tmp/ygo-right-origin-repro
cd /tmp/ygo-right-origin-repro
go mod init repro
go get github.com/reearth/ygo@v1.7.1
```

Create `main.go`:

```go
package main

import (
	"encoding/hex"
	"fmt"
	"log"

	"github.com/reearth/ygo/crdt"
)

func main() {
	// These two updates were generated by Yjs 13.6.30:
	// 1. clientID=1 inserts "ab" into Y.Text("content").
	// 2. clientID=2 applies update 1, then inserts "X" at index 1.
	updates := []string{
		"01010100040107636f6e74656e7402616200",
		"01010200c401000101015800",
	}

	doc := crdt.New()
	for _, encoded := range updates {
		update, err := hex.DecodeString(encoded)
		if err != nil {
			log.Fatal(err)
		}
		if err := crdt.ApplyUpdateV1(doc, update, nil); err != nil {
			log.Fatal(err)
		}
	}

	fmt.Printf("%q\n", doc.GetText("content").ToString())
}
```

Run it:

```sh
go run .
```

Actual:

```text
"abX"
```

Expected:

```text
"aXb"
```

## Yjs expected result

The same updates produce `"aXb"` with Yjs:

```js
const Y = require('yjs');

const updates = [
  '01010100040107636f6e74656e7402616200',
  '01010200c401000101015800',
].map((hex) => Buffer.from(hex, 'hex'));

const doc = new Y.Doc();
for (const update of updates) {
  Y.applyUpdate(doc, update);
}

console.log(JSON.stringify(doc.getText('content').toString()));
```

Output:

```text
"aXb"
```

## Suspected cause

The second update decodes in Yjs as an item with both boundaries:

```text
id          = { client: 2, clock: 0 }
origin      = { client: 1, clock: 0 }
rightOrigin = { client: 1, clock: 1 }
content     = "X"
```

ygo appears to resolve `Origin` into `item.Left`, but not `OriginRight` into `item.Right`, before calling `item.integrate`. Since `item.integrate` uses `item.Right` as the scan stop boundary, `item.Right == nil` lets the conflict scan run past the intended right boundary and place `"X"` after `"b"`.
