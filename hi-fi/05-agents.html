Purpose

One screen to see every agent in this workspace, who hosts them, what they're doing, and how much attention they're owed (for-me count). Grouping by daemon keeps ownership readable.

User experience

  • Cards sort by status within each daemon group (running → idle → paused). Offline daemons collapse to a single muted band.
  • The for-me chip is the only loud signal on a card — it's how operators triage who needs intervention.
  • Paused agents get an inline "Resume" — no detail-page detour for a one-click action.
Triggers
• New agent: the single global "New agent" button → opens form B.
• Open detail: click anywhere on a card → routes to /agents/:id.
• Resume / pause: inline button → POST /api/agents/:id/runs with action.
• Filter: the filter input narrows by name, role, daemon, or status (status:running, daemon:prod).

Purpose

Provision a new agent on a specific daemon. Daemon selection is explicit — never inferred — so users see exactly where this agent will run.

User experience

  • Form is single-step. The visible radio list of daemons doubles as a status display — offline daemons are disabled in place.
  • The handle preview shows @cassia formatted like a chip; we live-check uniqueness inside this workspace.
  • System prompt is optional and collapsible; users can ship the agent and edit later.
Triggers
• Open: "New agent" button on roster, sidebar, or anywhere we expose it (always routes to this same form).
• Create: POST /api/workspaces/:id/agents body: {handle, name, role, daemon_id, workspace_root, system_prompt?}.
• After create: close modal → route to agent detail (C); daemon picks up the agent on next check-in (typically < 5s).
• No online daemons: disable submit; show inline link to "Deploy a daemon" (Flow 04).

Features for engineering

  • Backend creates the agent and emits a daemon-targeted event; daemon claims it on next check-in.
  • Default workspace root suggested from daemon config, editable.
  • Handle uniqueness check: 200ms debounce against the workspace's agent + user handles.

Purpose

Operate one agent. The page exists to answer four questions quickly: is it running? · who's hosting it? · what is it touching right now? · is anyone waiting on it?

User experience

  • The handle and tinted chips make species (agent) immediately legible without making it the loudest signal.
  • Owning daemon is in the right rail with a one-click route — when a daemon goes stale, the operator can pivot from here.
  • "Run prompt" opens a small drafter inline; Pause immediately halts the current run.
  • Inbox card mirrors the layout in Flow 06 for muscle memory.
Triggers
• Pause / Resume: POST /api/agents/:id/runs with {action: 'pause'|'resume'}.
• Run prompt: opens an inline composer → POST /api/agents/:id/runs with {prompt}.
• Open daemon: right-rail card → daemon detail (Flow 04 C).
• View inbox: right-rail card or "View inbox →" → Flow 06.
• Archive: Danger Zone → confirmation; archived agents are read-only and stop receiving inbox events.

Engineering spec — full surface

Routes (FE)
/w/:slug/agents · /w/:slug/agents/new (modal) · /w/:slug/agents/:id
APIs (BE)
GET /api/workspaces/:id/agents — list, with daemon + run + counts.
POST /api/workspaces/:id/agents body: {handle, name, role, daemon_id, workspace_root, system_prompt?}
GET /api/agents/:id · PATCH /api/agents/:id (rename, change daemon, edit prompt)
DELETE /api/agents/:id (archive)
POST /api/agents/:id/runs body: {action: 'start'|'pause'|'resume', prompt?}
GET /api/agents/:id/runs?limit=20
Identity
Backend identity is UUID; handle is renameable. Daemon-acting requests pass X-Codesk-Acting-Agent-ID: <uuid>. Handles are unique within a workspace, scoped to both users and agents (no @foo collision).
Daemon ownership
Each agent has exactly one daemon_id. Moving an agent to a different daemon is a PATCH; the source daemon releases the agent on next check-in, target claims it on its next check-in. Agents on offline daemons are visible but read-only.
Run model
Run status: running · idle · paused · errored. agent_runs rows track each run. The current/active run is denormalized on the agent for display speed.
Components
<AgentRoster>, <AgentCard>, <NewAgentModal>, <AgentDetail>, <RunControls>, <AgentRecentActivity>, shared <DaemonOwnerPill>.
Live updates
Roster subscribes to workspace SSE; agent detail subscribes to agent.:id.* channel for run state, log tail, and inbox count deltas.
Edge cases
• Daemon offline → all its agents render dimmed, "Resume" buttons disabled with a tooltip linking to the daemon.
• Handle collision on create → 409 with suggestions.
• Archive while running → confirm + soft stop. Reactivating reuses the same UUID; handle may be reclaimed if free.
