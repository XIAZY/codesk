Purpose

The shell is the home view after auth. Three persistent regions: navigate (left), do (center), context (right). It avoids burying anything important behind a click and matches the user's mental model: files on the left, work in the middle, conversation on the right.

Three regions — what's where

  • Left (248px): workspace switcher, global search, top nav (Home / Activity / Threads), document tree, agents summary, account footer.
  • Center (fluid): doc toolbar (breadcrumb + presence + share), then the editor surface. The editor is the only place that opens a Yjs websocket; switching docs closes the previous socket and opens a new one.
  • Right (320px): tabs for Threads on this doc, Activity, People. Threads tab is the default.
Triggers
• Switch doc: click in left tree → push /w/:slug/d/:docId → close old Y socket, open new one. URL is shareable.
• New doc: "+" next to Documents label OR ⌘N. Inline-renames the new file immediately.
• Open threads on a range: select text in the editor → small floating action appears with "Open thread" (see Flow 03).
• Switch workspace: click the top-left workspace pill → opens picker overlay → routes to /w/:other-slug.
• Right-pane tab: click Threads / Activity / People. State persists per workspace.
• Cmd-K palette: jump to any doc, agent, daemon, thread by name; opens over the shell, dims it.

Engineering spec — full surface

Contracts, components, and the websocket lifecycle that this screen depends on.
Route
/w/:slug (no doc selected — show empty editor or last-opened doc) · /w/:slug/d/:docId (active doc).
APIs (BE)
GET /api/workspaces/:id/metadata → workspace + members + daemons + agents (lightweight, no doc bodies).
GET /api/workspaces/:id/documents → doc tree (id, path, title, head meta).
GET /api/documents/:id/threads → threads with anchor metadata for the active doc.
GET /api/workspaces/:id/activity?limit=20 → right-pane Activity tab feed.
GET /api/workspaces/:id/presences → poll/SSE every ~5s for sidebar/agent dots.
Websocket
WS /api/documents/:id/y — Yjs/y-protocol per active document only. Open on doc mount, close on unmount or doc switch. Reconnect with backoff on disconnect; show subtle "reconnecting…" pill in the toolbar.
Components
<Shell> (CSS grid) → <Sidebar> · <DocPane> · <ContextPane>. <DocTree> virtualizes once node count > 200. <CommandPalette> mounted at the shell root. Editor: TipTap with y-prosemirror binding.
State
Global Zustand (or React context): activeWorkspace, activeDoc, presence, threadCounts. Doc bodies are never in store — they live in the Y doc bound to the editor. The store holds head meta only.
Presence
Awareness piggybacks on the Y websocket for the active doc (cursors, selections, color). Outside the active doc, presence is server-pushed (SSE) and shown as dots on sidebar entries (e.g. "@cassia · editing /press-messaging").
Keyboard
⌘K palette · ⌘N new doc · ⌘/ open thread on selection · ⌘\ toggle left sidebar · ⌘. toggle right pane · ⌘1/⌘2/⌘3 right-pane tabs.
Performance
Only the active doc loads its Y history. Sidebar tree fetches metadata, not bodies. Right-pane thread list paginates. Activity feed is SSE with 50-item ring buffer.
Resilience
Websocket drop → IndexedDB persistence keeps the local Y doc editable; updates replay when reconnected. Show non-modal "Offline — your changes are saved locally" banner in the toolbar.
Tenancy guard
Every API and WS call carries the workspace ID derived from the route. Backend rejects cross-workspace access. The frontend should never read or render data for another workspace in this shell instance.
