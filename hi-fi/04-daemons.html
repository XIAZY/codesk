Purpose

Operators need a one-glance view of which local processes are alive. Liveness drives every agent's status — a stale daemon means its agents go stale too.

User experience

  • Counts at the top read like a small status board.
  • Rows have a stable visual identity: avatar tile + name + short fingerprint of the token hash.
  • Status chips share their dot color with sidebar dots elsewhere — same signal everywhere.
  • Row click → daemon detail (C). Overflow menu: rotate token, rename, delete.
Triggers
• New daemon: "New daemon" button → modal (B).
• Refresh: "Check liveness" button → re-fetches and animates updated dots.
• Open detail: click row → routes to /daemons/:id.
• Rotate / delete: overflow menu; rotate opens the same B modal with a "rotation" header.

Purpose

Mint a workspace-scoped daemon token, reveal it exactly once, and give the operator everything they need to bring the daemon online from a local machine.

User experience

  • Step 1 is a tiny "name + host (optional)" form (not shown — single input). Step 2, shown here, is the reveal.
  • The token block is treated as a security surface: amber wash, shield icon, "won't see it again" copy, mandatory "I've saved it" checkbox before Done enables.
  • Instructions tabs cover the common deploys: Docker Compose (recommended), Binary, K8s. Copy buttons on every code block.
  • While the modal is open, the bottom strip polls the daemon and flips to "Daemon online ✓" the moment it checks in; Done becomes enabled regardless of the checkbox once that happens.
Triggers
• Open: "New daemon" button on the list, or "Rotate token" on a row's overflow menu.
• Create: step 1 submit → POST /api/workspaces/:id/daemons → returns {daemon, token}. Token is held in component memory only.
• Copy / Download: client-side only; never re-fetches token.
• Done: closes modal → routes to daemon detail.
• Cancel: if the user closes without saving, show a confirmation: "The token is gone if you close. Rotate later to get a new one."

Features for engineering

  • Token never leaves component state. Don't put it in Redux, localStorage, URL params, or analytics events.
  • Auto-clear on modal close. Memory zeroing isn't possible in JS, but unmount cleanly.
  • Liveness poll: GET /api/daemons/:id/liveness every 3s while modal is open; cancel on unmount.
  • Rotation is the same modal with header "Rotate token". Old token is invalidated server-side at the moment the new one is minted.
  • Provide download as .env — the only outflow path other than copy.

Purpose

The operational dashboard for one daemon. It surfaces liveness history (because brief disconnects matter), the agents it owns (because deleting a daemon kills them), and the safe-to-reveal token fingerprint (the last 4 of the hash, not the secret).

User experience

  • Liveness chart is small and live-updated, not a focal point. The eye is drawn to the agents list.
  • Token fingerprint shown here is a one-way hash prefix — purely identity, not auth material.
  • Deleting a daemon shows a confirmation that names the agents that would be orphaned and offers to "Reassign agents to another daemon".
Triggers
• Rotate token: top-right → opens B with a "Rotation" header. New token shown once; old token invalidated atomically.
• Manage agents: link → routes to Flow 05 filtered by this daemon.
• Delete daemon: Danger Zone button → confirmation modal with agent reassignment option.
• Check-in update: live SSE updates the liveness dot, chart tail, and "Last sync" stat without reload.

Engineering spec — full surface

Routes (FE)
/w/:slug/daemons · /w/:slug/daemons/new · /w/:slug/daemons/:id
APIs (BE)
GET /api/workspaces/:id/daemons
POST /api/workspaces/:id/daemons → {daemon, token} (token returned exactly once)
POST /api/daemons/:id/rotate-token → new {token}
DELETE /api/daemons/:id body: {reassign_to?: daemon_id}
GET /api/daemons/:id · GET /api/daemons/:id/liveness?range=24h
POST /api/daemons/checkin (daemon-to-server; daemon-authenticated)
Daemon auth
Daemons authenticate with the workspace-scoped opaque token. Backend stores only SHA-256 hash. Token rotation invalidates the old hash atomically. Daemons send their acting agent's UUID via X-Notty-Acting-Agent-ID on requests made on behalf of an agent.
Liveness model
Status derived from last_checkin_at: online (< 60s), stale (60s–10min), offline (> 10min). Liveness history is checkpointed every minute for chart rendering.
Components
<DaemonList>, <DaemonStatusChip>, <DaemonCreateModal> (multi-step), <TokenRevealCard> (uses memoized in-component state, never global), <DaemonDetail>, <LivenessSparkline>.
Security rules
Token is in-component memory only. Never logged, never persisted, never sent to analytics. Copy/download are client-side. Rotation deletes the prior hash before responding so old daemons stop working immediately.
Edge cases
• Delete a daemon with running agents → confirmation lists impacted agents and offers reassignment.
• Daemon never checks in → modal shows "Still waiting…" with a "Show troubleshooting" toggle.
• Network blip → "stale" within 60s, dot turns amber across the app simultaneously.
Analytics
daemon.created · daemon.token_copied · daemon.token_rotated · daemon.deleted · daemon.first_checkin (with time-to-first-checkin metric).
