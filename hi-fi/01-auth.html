Purpose

Authenticate a returning account and hand the frontend a JWT + the list of workspaces they belong to. This screen is purely account-level — no workspace context yet.

User experience

  • Email + password, with inline validation (email shape, min length 8 on password).
  • Submit on Enter. Loading state on the CTA — never block the whole screen.
  • Bad credentials surface an inline non-modal error above the button: "Email or password doesn't match an account." Never leak which one failed.
  • On success: stash JWT in httpOnly cookie (or memory + refresh), then route to the picker.
Triggers
• Submit: click "Log in" or press Enter in either field.
• Switch to register: "Create one" link → routes to /register.
• Forgot password: link → routes to /forgot (out of scope of this flow).

Features for engineering

  • Form library: react-hook-form or equivalent. Show errors only after blur OR submit attempt — not on every keystroke.
  • Rate-limit feedback: after 5 failures, show a soft cooldown message; backend should also enforce.
  • Persist email locally so a fresh tab pre-fills it.
  • After success, call GET /api/workspaces immediately — if length === 1, skip the picker and route straight to /w/:slug.

Purpose

Create the global account (email is unique globally). Note: registration does not create a workspace and does not mint a handle — those happen at workspace creation. Per the README: "Handles are unique inside a workspace, not globally."

User experience

  • Three fields only: display name, email, password. Resist the urge to add anything else here.
  • Live password strength bar — visual only; the server is the gate.
  • On submit: account is created and the user is logged in. Route directly to Create workspace (D) — they have nothing to pick yet.
Triggers
• Submit: "Create account" → POST /api/auth/register → JWT issued → route to /workspaces/new.
• Already have account: footer link → /login.

Features for engineering

  • Email-already-taken error is surfaced inline under the email field. Offer a "Log in instead" affordance when it triggers.
  • Password rules client-side: 8+ chars, not in common-password list (zxcvbn score ≥ 2).
  • No email verification step in the MVP scope — accounts are usable immediately.

Purpose

Let the human pick which tenant they're entering for this session. The workspace boundary determines which documents, threads, daemons and agents they see — picking the wrong one shows nothing of theirs.

User experience

  • Each card shows: workspace avatar/name, slug, member count, daemon count, and the user's per-workspace handle (because it can differ across workspaces).
  • Cards are sorted by last-active-in-this-workspace, descending. Persist last-active workspace locally for one-click re-entry.
  • Bottom CTA always offers "Create a new workspace" — never bury it behind a menu.
Triggers
• Pick: click a card → route to /w/{slug}.
• Create: dashed CTA → routes to "D · Create workspace".
• Skip when alone: if GET /api/workspaces returns exactly one membership, never show this screen — route directly to /w/{slug}.

Features for engineering

  • Workspaces fetched once; cache for 5min, invalidate on workspace create/delete/leave.
  • Keyboard navigation: ↑ ↓ + ↵; ⌘K opens a small fuzzy search if > 5 workspaces.
  • Empty state: zero memberships → render "D" inline instead of a separate screen.

Purpose

Mint the tenant and the founder's in-workspace identity in one shot. The workspace owner is set to this account.

User experience

  • Slug auto-derives from name as the user types (kebab-case), but is editable.
  • Handle defaults to the local part of the email (amelia@… → @amelia), debounced live-check against the new workspace's namespace.
  • On success the user is dropped into the empty shell at /w/{slug} with a one-time onboarding nudge: "Deploy your first daemon to bring agents in", deep-linked to Flow 04.
Triggers
• Submit: "Create workspace" → POST /api/workspaces (body: name, slug, handle, display_name).
• Slug collision: backend 409 → inline error + suggest variants.
• After create: route to /w/{slug} and open onboarding popover anchored to the "Daemons" nav item.

Features for engineering

  • One transaction on the backend: create workspace + create workspace_user (owner role).
  • Slug/handle live-validation endpoints; show ✓/✗ inline. 200ms debounce.
  • Disable submit until name, slug, and handle all pass client-side validation.

Engineering spec — full surface

All the contracts this flow depends on, in one table.
Routes (FE)
/login · /register · /workspaces · /workspaces/new · /w/:slug (post-auth landing)
APIs (BE)
POST /api/auth/register → {jwt, account}
POST /api/auth/login → {jwt, account}
POST /api/auth/logout
GET /api/workspaces → list of memberships (workspace + handle)
POST /api/workspaces body: {name, slug, handle, display_name}
GET /api/workspaces/check-slug?slug= · GET /api/workspaces/:id/check-handle?h=
Auth model
JWT in httpOnly cookie. Token carries account_id only — workspace context is derived from the route (/w/:slug) and resolved against workspace_members on each request.
Components
<AuthShell> centered card layout · <LoginForm> · <RegisterForm> · <WorkspacePicker> · <CreateWorkspaceForm> · shared <FieldInput>, <PasswordStrength>, <HandlePreview>.
State / cache
useAuth() exposes account, jwt, workspaces, activeWorkspace. Workspaces cached via SWR with 5min staletime; invalidated on workspace create/delete/leave.
Error handling
Inline form errors (never modal). Auth failure is generic ("Email or password doesn't match"). Slug/handle collisions show suggestions. Network errors → inline retry button, never a full-page toast.
Edge cases
• Account with zero workspaces: route directly to /workspaces/new (skip picker).
• Account with exactly one workspace: skip picker on login.
• Expired JWT mid-session: redirect to /login?return=… preserving the deep link.
• Invite-only sign-ups (future): same form, gated by an invite-token URL param.
Accessibility
Full keyboard support; CTA is the default form action; password input announces strength via aria-describedby; workspace cards are <button> elements, not divs.
Analytics events
auth.register_submitted, auth.login_submitted, auth.login_succeeded, workspace.created, workspace.picked (with placement: picker / direct).
