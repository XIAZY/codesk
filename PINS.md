# PINS — the feature pin register

A pin is a test that goes red the day a business feature stops working. This file is the human-readable
index of what is pinned and, just as importantly, what is **not yet** pinned. It is reviewed like code:
any PR that adds, moves, or removes a pin updates its line here in the same PR. A pin that lives only in
a chat thread rots; one whose line fails review when stale does not.

Format: **Feature — breaks → the test that notices.** The gap list is simply the features whose line we
cannot honestly write yet; it is the program's backlog, ordered by business weight.

Seeded 2026-07-07 from the Tests-improvements scorecard (Tom/Bill/Deniz), alongside the contract tier
(PR #80) and its frontend consumption (PR2).

## Pinned

### Data integrity
- **Documents never lose data** — breaks → per-entity restart-survival tests + the compose sync-convergence E2Es (move / delete / concurrent-writer reconstruction) + checkpoint reconstruction (`test/regression`, `backend/internal/notty` store tests). _Documented exception: the WS-write ack gap is accepted-risk C3 — pinned as a decision in `test/regression`, not a test._

### API contracts
- **The workspace answer never changes shape by accident** — breaks → contract-tier golden rows `TestContractWorkspaceEmptyState` / `TestContractWorkspacePopulatedState` (`backend/internal/notty/contract_workspace_test.go`); a drift goes red naming the exact field.
- **The read surface never changes shape by accident (endpoint×state matrix)** — breaks → `TestContractEndpointsEmptyState` / `TestContractEndpointsPopulatedState` (`backend/internal/notty/contract_endpoints_test.go`): GET `/auth/me`, `/workspaces`, `/members`, `/daemons`, `/documents/{id}/threads`, `/threads/{id}` each pinned to a committed golden across empty + populated states, with the A1 never-null invariant on every collection row. A response-shape drift on any of them is a red, reviewable golden diff naming the exact field. _Corpus suite 2.1; grows one builder + one table row per endpoint added._
- **A successful write returns the shape the frontend renders from (mutation responses)** — breaks → `TestContractMutationResponseShapes` (`backend/internal/notty/contract_mutations_test.go`): workspace-create, document-create (idempotent), agent-create, thread-create, presence-upsert each pin their canonicalized response object to a golden. The frontend renders straight from these responses, so a create/update contract drift is a red diff. _Corpus suite 2.2._
- **Daemon-create returns a secret token, and no secret ever lands in a golden** — breaks → `TestContractDaemonCreateRedactsToken` (`contract_mutations_test.go`): asserts the enrollment token is present and non-empty (the installer needs it), then pins the daemon-create shape with the token redacted. A change to the daemon-create contract is still a reviewable diff, and a secret is never committed. _Corpus suite 2.4 (redaction)._
- **The load path (GET /workspace) and the reconnect path (workspace.snapshot WS event) serve the same shape** — breaks → `TestContractWorkspaceSnapshotRESTParity` (`backend/internal/notty/contract_parity_test.go`): every shared collection (users/daemons/agents/agentRuns/threads/agentEvents/presences/activities) is byte-identical after canonicalization across the two surfaces. A field added to one surface but not the other — which would half-render the app on one of the two hydration paths — is a red diff naming the collection. _Corpus suite 2.4 (parity)._
- **The agent.run.updated broadcast never leaks a run's secrets to workspace clients** — breaks → `TestContractAgentRunUpdatedBroadcastIsRedacted` (`backend/internal/notty/contract_run_redaction_test.go`): the broadcast strips `systemPrompt`, summarizes `prompt` to a ≤72-rune preview, caps `logTail` to the last `agentRunLogPreviewLines` (each ≤ `agentRunLogLineLimit`), and truncates `error` to `agentRunErrorLimit` — asserted on the WS event itself, captured off the broker. A refactor that starts broadcasting a raw run (a real data-exposure regression) goes red. _Corpus suite 3.1; complements the REST redaction pin `TestWorkspaceEndpointsTrimHistoricalAgentRunPayloads`._
- **A mutation broadcasts its change exactly once; a refused mutation broadcasts nothing** — breaks → the emission-count sweep in `backend/internal/notty/contract_emissions_test.go`: the daemon lifecycle (`TestContractDaemonLifecycleEmitExactlyOncePerChange`: create/check-in/delete → one `daemon.created`/`daemon.updated`/`daemon.deleted`, refused delete → 0) and the agent lifecycle (`TestContractAgentLifecycleEmitExactlyOncePerChange`: create/session/delete → one `agent.created`/`agent.updated`/`agent.deleted`, refused → 0), plus presence (`TestContractPresenceUpsertEmitsOncePerCall`: exactly one `presence.updated` per upsert — presence has no no-op suppression by design). A missing broadcast strands other clients; a double is a storm. _Corpus suite 3.2._
- **Every error is the same envelope `{"error": "<non-empty>"}`** — breaks → `TestContractErrorEnvelopePerClass` (`backend/internal/notty/contract_errors_test.go`): 400/401/403/404/409 each return exactly one `error` key with a non-null non-empty string at the right status, so the frontend parses any failure uniformly. The shape is uniform by construction (one `writeError` helper); the test samples the 4xx classes to catch a handler that bypasses it. _Corpus suite 2.3; 410/413 flow through the same helper and are covered for status by their own handler tests._
- **Collections are never JSON null** (the workspace-switch white-screen) — breaks → `TestWorkspaceResponseNeverNulls…` (backend, in-package) + the contract rows' A1 assertion + the frontend consumption test (`frontend/src/contractFixtures.test.ts`).
- **Snapshot presences are keyed and visible to the online ring** — breaks → `frontend/src/contractFixtures.test.ts` (populated golden → presence retrievable by actorId). _Pinned by PR2; the bug it caught is fixed in the same PR._

### Browser flows (end-to-end, Playwright vs the compose prod bundle)
- **The core browser flow works: login → workspace switch → open/edit a document** — breaks → `e2e/tests/smoke.spec.ts` core-flow test (production `vite preview` bundle + real compose backend, retries=0). The A→B switch into a fully idle workspace pins the **white-screen incident**: any uncaught exception on the switch fails via the `page.on('pageerror')` net. _Scope: the crash needs both sides (a `null` collection from the backend AND a frontend deref), so this row reds only when both #75's reducer-seam coercion and #76's never-null backend regress — it is the last net over the layered unit pins (#75 reducer test, #76 in-package never-null, the contract goldens), not the only one; red-proof captured `pageerror: f.threads is not iterable` on the both-sides revert._
- **A healthy thread anchor survives a document reopen (no false "anchor lost")** — breaks → `e2e/tests/smoke.spec.ts` false-orphan pin: a thread on a real Yjs relative position, after the doc is reopened and re-synced over the WS, must show no orphan warning. _Scope: defended in depth by #100's `ready` guard AND #40's post-sync `ytext.observe` re-classification; reds only when both regress (reproducing the original stuck false-orphan, `.thread-orphan-warning` count 1) while the core flow stays green._

### Agent wire-half (daemon ↔ backend protocol)
- **A daemon can act as an agent only via the acting-agent header, and only for an agent it owns** — breaks → `TestContractActingAgentTokenBoundary` (`backend/internal/notty/contract_acting_agent_test.go`): a daemon acting as its own agent is authorized, but presenting another daemon's agent id — or a non-existent agent id — is rejected (403). A regression that stopped checking daemon ownership would let a compromised daemon author as any agent in the workspace. _Corpus suite 4.2 (backend boundary)._
- **Contended agent-event claims: exactly one claimer wins** — breaks → `TestAgentEventContendedClaimPostgres` (`backend/internal/notty/server_test.go`) + `TestAgentEventClaimedByRejectsUnrelatedDaemon` / `TestAgentEventClaimedByStateMachine` (`store_postgres_fk_test.go`) — concurrent claimers race on live Postgres and exactly one wins; an unrelated daemon cannot claim; the claim state machine holds. _Corpus suite 4.1 (audited 2026-07-08, already covered)._
- **Deleting a daemon disconnects but never destroys its agents (reinstall keeps history)** — breaks → `TestContractDaemonDeleteDisconnectsAgents` (`backend/internal/notty/contract_daemon_disconnect_test.go`): daemon deletion is a soft delete, so the agent rows (and their run/event history) survive while the daemon stops being an active host. A regression to a hard/cascade delete — silently losing agent history on every reinstall — goes red. Token rotation on reinstall is pinned by `TestDaemonReinstallTokenRotatesDaemonToken` (`server_auth_test.go`). _Corpus suite 4.4._

### Notifications & inbox routing (muted inbox — task #2)
- **Muted never pushes** — a document edit with zero subscribers produces zero inbox rows, zero `agent.inbox.changed` doorbells, and schedules zero turns — breaks → `TestMutedDocumentUpdateDoesNotPushToNonSubscriber` (`backend/internal/notty/store_muted_inbox_test.go`, rows + doorbell) + `TestMutedEventNeverEntersPushedNotificationBoxes` (`daemon/internal/syncer/muted_box_test.go`, no turn). Anyone who re-introduces ambient push — even accidentally via the unknown-box→for_me default — goes red; the two `normalizeInboxBox` copies are kept in agreement by `TestNormalizeInboxBoxMutedNeverRoutesToPushedBox` (daemon) alongside the backend case.
- **Subscription is the only document→push path, and it respects quiescence** — a subscribed edit produces exactly one `general`-box card whose `available_at` slides with typing and matures 60s after the last batch; immature cards never enter listings/prompts — breaks → `TestSubscribedDocumentUpdatePushesToGeneralWithQuiescence` (`store_muted_inbox_test.go`) + the maturity filter on `listAgentEventsPostgres`. Endpoints (subscribe/unsubscribe/list, idempotent, cross-daemon 403, owner-passes-shared-boundary) are pinned by `TestDocumentSubscriptionEndpoints` with golden rows `document_subscriptions_{empty,populated}`.
- **A thread event still rings the inbox doorbell (the surviving positive doorbell pin)** — breaks → `TestThreadDoorbellFiresForMentionOnCreateAndReply` (`store_muted_inbox_test.go`): after the document doorbell is removed, thread create and reply must still broadcast exactly one `agent.inbox.changed` (thread.mentioned, for_me). Subscriptions join the FK cascade graph — `TestDocumentSubscriptionsCascadeOnAgentDelete`.
- **Document *creation* is the one document push, and it rides poll+maturity not the doorbell (task #3)** — `Store.CreateDocument` emits exactly one `document.created` `general`-box card per workspace agent except the creator (`shouldNotifyAgentPostgres` actor-exclusion, human AND agent creators), `available_at = now + 60s`, dedup key `document-created:<docID>:<agentID>`, and rings zero doorbells — so an N-document burst collapses into N cheap rows the poll batches into one bounded turn per agent (the top-3 wake cap does the rest). Emitted from the creation seam, never by weakening the `UpdateID <= 1` edit-skip; hidden docs excluded; idempotent-replay create (the `CreateClientOperationID` early return) double-cards no one; completing a created card advances the doc watermark. Breaks → the `TestDocumentCreated*` suite (`backend/internal/notty/store_document_created_test.go`): non-creators carded once, creator excluded, replay zero, hidden zero, burst→N-rows-zero-doorbells, completion advances watermark, and a post-create edit to an unsubscribed doc still pushes nothing (the task #2 muted invariant stays intact).
- **Bare `list-inbox` shows all boxes, but the muted count can never wake an agent** — breaks → `TestBareListInboxReturnsAllBoxesIncludingMuted` (an empty box query returns for-me + general + muted; each `--box` still filters). The wake prompt carries a count-only muted pointer, and it is decoration that never admits a turn: the per-cycle poll never issues a bare/all-box fetch (`TestAutomationNeverIssuesBareAllBoxInboxFetch`, muted fetched only at turn-assembly), a muted item can't change the for_me/general suppression signature (signature-exclusion assertions in `TestMutedEventNeverEntersPushedNotificationBoxes`), and a firing turn shows the count without details (`TestDriveAgentAutomationStartsNotificationTurnFromInbox`). A regression that let muted into the poll, the signature, or the details reds here — that's the guard against reviving ambient wakes through the count line.

### Frontend units (vitest)
- **The workspace realtime lifeline (useWorkspace hook) loads, dispatches, survives bad frames, and reconnects** — breaks → `frontend/src/useWorkspace.test.tsx` (five cases, previously zero): loads the initial snapshot over REST into the reducer; marks connected on socket open and dispatches every frame; ignores a malformed frame without crashing or mutating state; reconnects with exponential backoff (1000ms → 2000ms) after a close; and closes the socket + cancels the reconnect on unmount. A dropped snapshot, a crash on a bad frame, a broken backoff, or a leaked socket is caught here in isolation. _Corpus suite 5.1._
- **The thread/time view helpers stay honest** — breaks → `frontend/src/logic.test.ts` (audited 2026-07-08, already covered): `relativeTime` (formats past timestamps, guards bad input), `threadReplyLabel`/`threadReplyCount` (a starter message is not a reply), and `resolveThreadAnchorLive` (the full anchor-pattern matrix — stable-after-edit, collapsed-range orphan, mid-range insert stays anchored, and the pre-sync empty-ydoc reproduction). _Corpus suite 5.2; the audit added the register line, the tests already existed._

### Agent lifecycle (daemon-side, in-process)
- **Session state machine** — idle/working/disconnected transitions, resume-falls-back-to-fresh, steer-vs-queue on a busy session, stale-process events ignored, idle-notification-once — breaks → the fake-driver suite in `daemon/internal/syncer/agent_sessions_test.go` (`TestAgentSessionResumeFailureStartsNewSession`, the `BusyForMe`/`BusyGeneral` steer/queue tests, the missing/unregistered-runtime disconnect tests, `…IgnoresEventsFromStaleRuntimeProcess`, `…IdleNotificationStartsOncePerInboxSignature`).
- **A failed turn-start leaves no stale active turn** — breaks → `TestClaudeStartTurnWriteErrorLeavesNoStaleActiveTurn` (`daemon/internal/syncer/claude_driver_test.go`): a StartTurn whose write fails must clear the turn it optimistically armed, or a later steer targets a phantom turn.
- **A dropped turn-end can't wedge a session (guaranteed lifecycle delivery)** — breaks → `TestClaudeFullChannelCannotLoseTurnEnd` + `TestClaudeStopSignalReleasesBlockedLifecycleEmit` (`daemon/internal/syncer/claude_driver_test.go`): even when the event channel is full, the turn-end that returns a session to idle must still be delivered — a lost turn-end strands the session in `working` — and a stop signal releases a lifecycle emit blocked on that full channel so a stop can't wedge it either. _Fixed + pinned by #99 (tasks #12/#13). A wedge from the runtime process itself going silent (external code) still has no detection — revisit with a production incident, per the ruling that dropped the observe-only watchdog._
